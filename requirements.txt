# WHY the pins stay a matched pair: torch 2.9.x only imports cleanly against the
# torchaudio built from the same release; a mismatch dies inside the separation
# worker with `ImportError: cannot import name ... from torch._C`.
#
# WHY this file is the CPU/dev path and never the CUDA path: the PyPI default of
# `torch==2.9.0` is not one wheel but three different builds -
#   win_amd64            CPU-only      (torch.cuda.is_available() -> False)
#   manylinux x86_64     CUDA build    (pulls the nvidia-* runtime wheels)
#   macosx arm64         Metal/MPS
# CUDA-enabled wheels exist only on https://download.pytorch.org/whl/<cudaversion>
# and must be requested with an explicit index URL; install requirements-cuda.txt
# for them (docs/PACKAGING.md, section "CUDA Installation").
# Verified 2026-10-02 against PyPI: torch/torchaudio/onnxruntime publish cp311
# wheels for win_amd64 and manylinux, so `pip install -r requirements.txt` needs
# no compiler and no marker on any of the three supported OSes.
